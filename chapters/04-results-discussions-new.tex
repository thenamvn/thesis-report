\section{Overview of Developed System}
\label{sec:system-overview}

The TEKUTOKO platform has been fully developed and deployed, featuring a modern, responsive user interface. The following visual evidence demonstrates the key components of the live system.

\subsection{Authentication and Dashboard}
Users are greeted with a secure login interface implementing JWT-based authentication, alongside OAuth 2.0 integration for seamless access via Google and LINE accounts (Figure \ref{fig:ui-login}). Upon logging in, the Dashboard (Figure \ref{fig:ui-dashboard}) serves as the central discovery hub. It displays all active rooms available for joining, supports keyword-based search, and features a specialized "Nearby" filter that utilizes GPS to locate rooms within the user's vicinity.

\section{Non-Functional Testing Results}
\label{sec:non-functional-testing}
Non-functional testing focused on the system's reliability, code quality, and performance under load, confirming the robustness of the microservice architecture.

\subsection{Backend Unit Testing}
To ensure the logic integrity of individual components, unit tests were implemented for the backend services using the Jest framework. The tests cover critical paths including user authentication, score calculation algorithms, and database operations.

The test suite achieved a high level of code coverage for core business logic, ensuring that edge cases in scoring and game state management are handled correctly.

\subsection{System Performance and Load Testing}
\label{sec:load-testing}

This scenario validates the architectural choices and answers the scalability requirements, examining whether the microservice-based architecture provides the performance required for real-world deployment.

The `/api/discovery/rooms` endpoint and the socket connection handler were subjected to a progressive load test using `k6`, graduating from 1 to 100 concurrent virtual users over a 10-minute period.

\textbf{Key Performance Metrics:}
\begin{itemize}
    \item \textbf{Peak Throughput:} The system sustained an average of \textbf{280 Requests Per Second (RPS)} at peak load.
    \item \textbf{Average Response Time:} The average response time remained under \textbf{300ms} at 100 concurrent users, well within the acceptable range.
    \item \textbf{Error Rate:} The test completed with a \textbf{0\% error rate}, validating the stability of the Node.js event loop under stress.
\end{itemize}

\begin{figure}[htbp]
\centering
\includegraphics[width=0.9\textwidth]{figures/load-test-results.png}
\caption{API Response Time Under Increasing Load}
\label{fig:load-test-results}
\end{figure}

These results confirm that the stateless architecture is robust. The ability to handle high concurrency with low latency proves the effectiveness of the chosen tech stack (Node.js/Socket.io) for real-time applications.
